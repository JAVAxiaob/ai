# 第八章：算法综合实战 —— 从零搭一个可运行的分类模型

> 面向对象：零基础小白
> 本章目标：把前面学过的算法串起来做一个完整的端到端流程。

---

## 一、本章任务

**目标**：给定一个二维模拟数据集（类似两个半月/同心圆），训练一个分类器，并完整走一遍「数据生成 -> 可视化 -> 模型选择 -> 训练 -> 评估 -> 结果可视化」的流程。

这是机器学习的「Hello World」级项目，但涵盖了所有真实项目中会遇到的核心问题。

---

## 二、完整流程分步拆解

### Step 1: 生成/理解数据（EDA）

在真实项目中，第一步永远是**理解数据**，而不是写模型。

**EDA（Exploratory Data Analysis）要点**：
- 每个特征的分布（均值、方差、分位数）
- 特征之间的相关性（防止冗余特征）
- 特征和标签的关系（哪些特征对分类最有用）
- 缺失值、异常值、类别不平衡

**在我们的模拟数据中**：utils.py 的 make_classification_data 生成二维非线性可分数据（类似 scikit-learn 的 make_moons / make_circles）。

一个关键决策：**数据是否线性可分？** 直接决定了你该选什么模型：
- **线性可分**：Logistic Regression、Linear SVM 就够了，不用上 MLP
- **非线性可分**：需要核方法（Kernel SVM）、树模型（Random Forest / XGBoost）或神经网络（MLP）

**永远先画散点图**。二维数据可以直接可视化。高维数据可以用 t-SNE / UMAP 降到 2D 再画。

---

### Step 2: 切分训练集/验证集/测试集

**留出法（Holdout）**：70% 训练，30% 测试 或 60% 训练 / 20% 验证 / 20% 测试。简单，适合大数据。

**交叉验证（Cross-Validation）**：把数据分成 K 份，每次用 K-1 份训练，1 份验证，重复 K 次取平均。更稳定的评估，推荐 K=5 或 10。

**重要**：
- 测试集只能用**一次**！（不能用测试集调超参，那等于在测试集上训练）
- 验证集用于调参（模型选择）
- 最终评估报告要用测试集

---

### Step 3: 数据预处理

三种最常见的预处理：

| 方法 | 做法 | 适用场景 |
|:---:|:---|:---|
| **Standard Scaler** | (x - mean) / std | 默认首选。大多数基于梯度的模型（LR、SVM、MLP、Transformer）要求输入大致在 0 均值 1 方差。 |
| **Min-Max Scaler** | (x - min) / (max - min) -> [0, 1] | 当你需要固定范围时（图像像素通常已经是 [0, 255] 或 [0, 1]）。 |
| **Robust Scaler** | (x - median) / IQR | 数据有大量异常值时（中位数和 IQR 对 outlier 不敏感）。 |

**原则**：Scaler 的 mean/std 必须**只在训练集上计算**，然后在验证集/测试集上用同样的 mean/std 去变换。否则你把测试集的信息泄露到了训练中（data leakage）。

---

### Step 4: 选择并训练多个模型做 baseline

**不要一开始就上大模型**。先跑一套轻量基线，看看「不花力气能做到什么精度」，然后再决定是否需要更复杂的模型。

**推荐的 baseline 组合**（适用于表格/低维数据）：

| 模型 | 优点 | 缺点 | 典型超参 |
|:---:|:---|:---|:---|
| **Logistic Regression** | 快、可解释、参数少 | 只能学线性边界 | C (正则强度) |
| **KNN** | 简单、无需训练（惰性学习）| 推理慢（和所有训练点比距离）、维度诅咒 | k (邻居数) |
| **Decision Tree** | 可解释（画出来能看规则）| 容易过拟合、不稳定 | max_depth, min_samples_leaf |
| **Random Forest** | 准、对超参不敏感、抗过拟合 | 训练慢、不可解释 | n_estimators, max_depth, min_samples_leaf |
| **SVM (RBF kernel)** | 准、对高维小数据友好 | 慢（O(n^2)~O(n^3)）| C, gamma |
| **MLP (2 层)** | 可以学任意非线性 | 需要调参、对数据规模敏感 | hidden_dim, lr, epochs |

**在本章的 demo 中**，我们训练了 KNN、Naive Bayes、Logistic Regression、Decision Tree 四个模型，并画出了每个模型的决策边界（decision boundary）——直观看到不同模型的「风格差异」。

---

### Step 5: 超参数调优

**网格搜索（Grid Search）**：在候选参数的笛卡尔积上穷举。简单但参数多时指数级爆炸。

**随机搜索（Random Search）**：从参数分布中随机采样。Bergstra & Bengio (2012) 证明「在大多数实际场景下随机搜索比网格搜索更高效」，因为有些超参比其他更重要。

**贝叶斯优化（Bayesian Optimization）**：用一个代理模型（如 Gaussian Process / Tree-structured Parzen Estimator）去建模「超参数 -> 验证集精度」的函数，有策略地选下一组超参数。比网格/随机搜索高效得多，但实现复杂。推荐库：optuna、hyperopt。

**一个实用的两阶段策略**：
1. **第一阶段（粗搜索）**：大范围随机搜索 50-200 组超参，大致了解好参数在哪里。
2. **第二阶段（精细搜索）**：在好参数附近做密集的网格搜索或贝叶斯优化。

---

### Step 6: 评估指标 —— 精度高不等于一切都好

**分类任务的常见指标**：

| 指标 | 公式 | 适用场景 |
|:---:|:---|:---|
| **Accuracy 精度** | (TP+TN) / Total | 类别均衡的简单场景。**在不平衡数据上会骗人**（99% 是正样本时，全预测正 = 99% accuracy）。 |
| **Precision 准确率** | TP / (TP+FP) | 「你的预测正样本中，多少是真的正样本」。**当误报代价高时关注**（如垃圾邮件分类：把合法邮件当垃圾很糟糕）。 |
| **Recall 召回率** | TP / (TP+FN) | 「真实正样本中，多少被你找出来了」。**当漏报代价高时关注**（如癌症筛查：漏诊比误诊更可怕）。 |
| **F1 Score** | 2 * P * R / (P + R) | Precision 和 Recall 的调和平均。两者都要好时用。 |
| **AUC / ROC-AUC** | 阈值曲线下面积 | 需要在不同分类阈值下比较模型时。对类别不平衡不敏感。 |
| **Log Loss / Cross Entropy** | -sum(y log p) / N | 当你需要「好的概率校准」而不只是正确分类时（如广告点击率估计）。 |

**选择哪个指标取决于你的业务目标**。没有「一个指标对所有问题都最好」这种事。

---

### Step 7: 误差分析 —— 你的模型错在哪里？

训练完模型后的最重要一步是**理解模型为什么错**。盲目堆模型层数没用。

**关键问题**：
1. **模型在哪些样本上错了？** 把错分的样本拿出来看（图像就画图，文本就看原文）。是不是这些样本本身就标注错了？（真实数据标注质量通常只有 85-98%）
2. **错误类型有规律吗？** 例如你的猫狗分类器在「雪地里的狗」上总是错（可能训练集中雪地样本少）-> 你需要针对性补数据。
3. **模型的预测置信度如何？** 模型对某些样本的预测是 51% vs 49%（它也很不确定，可能问题本身就模糊），而对另一些样本是 99% 却预测错了（模型有盲区）。
4. **混淆矩阵是什么样的？** 多分类任务的混淆矩阵可以直接告诉你「哪两类最容易被弄混」。

---

### Step 8: 模型集成（Ensemble）—— 把多个模型变成一个更强的模型

当你有多个 baseline 模型时，可以把它们组合起来。常见方式：

| 方法 | 直觉 | 代表算法 |
|:---:|:---|:---|
| **Voting / Averaging** | 多个模型投票 / 取概率平均 | 最简单的集成。模型独立且多样化时有效。 |
| **Bagging** | 在不同数据子集上训练独立模型，最后平均。降低方差。 | Random Forest（在不同 bootstrap 样本上训练不同的树）|
| **Boosting** | 串行训练，每个新模型关注「上一个模型错的样本」。降低偏差。 | AdaBoost, GBDT, **XGBoost**, **LightGBM**, CatBoost |
| **Stacking** | 用一个 meta-learner（如 LR）学习「如何组合底层模型的预测」| 复杂但可能更强。Kaggle 冠军常用。 |

**经验法则**：
- XGBoost / LightGBM / CatBoost 是表格数据的默认王者
- 图像/文本/语音等非结构化数据 -> 深度学习（CNN / Transformer）
- Kaggle 比赛的常见套路：「大量特征工程 + LightGBM + 小模型 NN 做 stack」

## 四、问题与答案解析

### Q1：如果精度一直上不去，我应该怎么办？按什么顺序排查？

**答**：一个实用的排查顺序（从高概率 -> 低概率）：

1. **检查数据质量**（最常见的坑）：标签对吗？特征有没有缺失值/异常值？有没有训练-测试泄露？（比如 scaler 用了测试集的 mean）
2. **检查 label 分布**：是不是类别极度不平衡？如果是，用 class weight / oversampling (SMOTE) / F1 指标而不是 accuracy。
3. **检查模型容量**：如果 train accuracy 也低（欠拟合）-> 增大模型（更深 MLP、更多树、更高 C 的 SVM）；如果 train 高但 valid 低（过拟合）-> 加数据、加正则、减小模型。
4. **检查超参数**：用随机搜索或 optuna 调一批超参，默认超参几乎永远不是最优的。
5. **检查优化器/学习率**：深度学习模型对 lr 极敏感。太大 loss 爆炸，太小收敛慢。推荐从 1e-3 开始，配合 ReduceLROnPlateau 或余弦退火。
6. **检查输入表示**：图像要不要做 data augmentation（随机裁剪/翻转/颜色抖动）？文本要不要更好的分词/预训练 embedding？
7. **换模型架构**：如果上面都做了还是不行，换更强的模型（从 LR -> Random Forest -> XGBoost -> 小 MLP -> 预训练大模型）。
8. **加数据**：最终的杀手锏。大多数 ML 问题在数据×10 后精度会显著提升。
9. **重新审视任务定义**：你定义的「正确答案」真的合理吗？有时问题本身就没有唯一答案（主观性任务）。

---

### Q2：为什么树模型（Random Forest / XGBoost）在表格数据上这么强？什么时候选深度学习？

**答**：树模型的优势：

1. **对不同尺度的特征天然友好**：一个特征是 [0, 1]，另一个是 [0, 1e6] —— 树完全不在乎（因为是按阈值分裂，不是按距离/内积）。LR/SVM/NN 需要精细的归一化。
2. **自动特征交互**：树可以学到「当 A > 5 且 B < 3 时是正类」这种高阶交互，而 LR 需要你手动做 feature cross。
3. **对异常值鲁棒**：一个极端样本通常只会影响少数叶子，不会像 LR 那样把整个超平面拉歪。
4. **可解释性**：可以画出树、可以看 feature_importance（每个特征对分裂的贡献）。
5. **训练快、调参简单**：默认参数就不错，少量调参就接近最优。

**深度学习的优势**：
- **结构化原始数据（图像/语音/文本）**：输入有天然的空间/时序结构，CNN/Transformer 可以自动提取层级化特征。
- **海量数据（100 万+样本）**：当数据多到树模型的 O(n) 或 O(n log n) 也很慢时，且数据中的模式复杂到树很难学，深度学习开始反超。
- **迁移学习可用时**：有大规模预训练模型（ImageNet 预训练的 ResNet、BERT/GPT）时，微调 1 小时远胜过从零训一个树模型。

**分界线（经验）**：
- 表格数据 + <100 万样本 -> **XGBoost / LightGBM**（默认首选）
- 表格数据 + >100 万样本 + 特征有空间/时序结构 -> 试试 MLP / TabNet / Transformer
- 图像 / 文本 / 语音 / 视频 -> **深度学习（CNN / Transformer）**

---

### Q3：为什么需要训练集/验证集/测试集？只用训练集和测试集不够吗？

**答**：如果只用两个集合并用测试集来调超参数，你实际上在「用测试集训练超参数」—— 测试集的信息通过你的选择泄露了进去。最终的测试精度会**高估**真实泛化能力（在完全新的数据上的表现）。

**正确的三分离**：
- **训练集 (60%)**：训练模型参数
- **验证集 (20%)**：选模型、调超参、做 early stopping、选数据增强策略
- **测试集 (20%)**：最终一次性评估。只能用一次！

**在小数据上的替代方案**：用 10-fold CV 代替「训练集+验证集」。测试集仍然只在最后用一次。

---

### Q4：过拟合和欠拟合，哪个更严重？如何诊断？

**答**：先画图看两条曲线（train loss vs valid loss）：

| 现象 | 诊断 | 怎么办 |
|:---:|:---:|:---|
| Train loss 高，Valid loss 高 | **欠拟合**（模型太简单/训练太短） | 增大模型、训练更久、减小正则化、增大 lr |
| Train loss 低，Valid loss 高 | **过拟合**（模型记忆了训练集） | 加数据、加正则（weight decay / dropout / L1）、减小模型、early stopping、数据增强 |
| Train loss 低，Valid loss 低 | **完美** | 收工，或尝试更多模型看是否还能提升 |
| Valid loss 先降后升 | **典型过拟合** | 在最低点停止训练（early stopping）|

**哪个更严重？** 在实际项目中过拟合通常更常见（模型越来越大 + 数据永远不够），欠拟合用更大模型就能解决。但过拟合的根源是「数据不足」，加数据比加正则更有效。

**奥卡姆剃刀原则**：在验证集精度相同的模型中，选最简单的那个（参数更少/训练更快/可解释性更好）。

---

### Q5：Batch Normalization 放在激活函数前面还是后面？有什么影响？

**答**：这是一个长期争论的问题。

**原始 BN 论文**（Ioffe & Szegedy, 2015）推荐：Linear -> BN -> Activation
原因：BN 本来就是要让下一层输入「标准化」，所以放在激活前（此时是前一层 Linear 的输出）。

**实践中发现**：在某些模型上 Linear -> Activation -> BN 效果也不错甚至更好。

**现代共识**（特别是有残差连接后）：
- Pre-activation ResNet: BN -> Activation -> Conv（「先归一化再非线性」）
- 普通 CNN: Conv -> BN -> ReLU（这个顺序最常用，方便把 BN 和 Conv 绑在一起部署）
- 在 MLP 中：Linear -> BN -> ReLU 或 Linear -> ReLU -> BN，效果相近，哪个先试都行

**BN 的真实作用**：原论文说是「减少 Internal Covariate Shift（每层输入分布变化）」。后续研究认为其实 BN 主要是**让优化更平滑（loss landscape 更光滑）** + 提供**微弱的正则化**（batch 内的均值/方差有噪声）。不管真实原因是什么，BN 在实践中几乎总是有帮助。

---

### Q6：当你发现所有模型都表现很差（只有 55% accuracy，随机是 50%），可能是什么根本原因？

**答**：这是「特征不够强」的经典信号。模型不是魔术 —— 如果输入特征不包含区分正负类的信息，再强的模型也白搭。

**按概率从高到低排查**：

1. **标签噪声**：训练集的标签本身就有 30% 是错的。人工抽样检查 100 个样本的标注质量。
2. **数据泄露（反方向）**：训练集和测试集不是同分布（train 是夏天的数据，test 是冬天的数据）。解决：画 t-SNE 看两个集是否混在一起。
3. **特征工程缺失**：你给模型的是「原始字符串」而不是「词频向量/embedding」，是「原始时间戳」而不是「一天中的第几小时、星期几」等有用特征。
4. **特征缩放错误**：SVM/LR/MLP 对特征尺度敏感，如果一个特征是 1e6 量级另一个是 0-1，模型几乎只看大的那个。先用 StandardScaler。
5. **问题本身很难**：有些问题真的没有好的规律（如「预测明天是否下雨」受混沌系统支配），或者需要外部信息（你的数据里没有）。此时要降低预期，或找新数据源。

**一句话总结**：**特征 >> 模型**。一个好特征 + 简单 LR，通常胜过坏特征 + 大 Transformer。Andrew Ng 说过「做 ML 80% 的时间在处理数据」，说的就是这个。

---

### Q7：Dropout 在测试时为什么要关掉？它和权重衰减有什么关系？

**答**：训练时 Dropout 随机以概率 p 把某些神经元置 0（「每次训练一个不同的子网络，最后隐含地集成所有子网络」）。测试时用完整网络的所有神经元，但需要把激活值按 (1-p) 缩放（或训练时反向缩放 inverted dropout，这样测试时什么都不用做，这是实际实现中常用的方式）。

**为什么需要缩放**：直觉——训练时每个神经元输出的期望是 (1-p)*w*x（因为 p 概率被 0 掉），测试时如果不缩放，期望是 w*x。为了保持同样的期望值范围，测试时要乘 (1-p)。实际实现中通常用「inverted dropout」：训练时除以 (1-p)，测试时不做任何事。

**和权重衰减 L2 的关系**：Wager et al. (2013) 证明在某些条件下（如线性模型）Dropout 在数学上等价于一种自适应的 L2 正则化。不同特征被 dropout 的概率与该特征的系数大小有关。实践中两者经常同时使用（如 weight_decay=1e-4 + dropout=0.1），效果叠加。

### Q8：学习率调度（learning rate schedule）有哪些常见策略？

**答**：训练深度学习时 lr 不是固定的，而是随时间衰减。常见策略：

| 策略 | 做法 | 适用场景 |
|:---:|:---|:---|
| **Step Decay** | 每 N 个 epoch 乘以 0.1 | 简单基线。 |
| **Exponential Decay** | lr[t] = lr0 * exp(-k*t) | 连续平滑衰减。 |
| **Cosine Annealing** | lr[t] = lr_min + 0.5*(lr0-lr_min)*(1+cos(t*pi/T_max)) | 现在的默认首选，配合 warmup 使用（Transformer 标配）。 |
| **ReduceLROnPlateau** | 监控 valid loss，当 loss 多轮不降时 lr *= 0.5 | 简单模型（MLP/CNN）上很好用，不需要预先指定总 epoch。 |
| **One-Cycle LR** | lr 先从低升到最大值，再降下来，最后再降到很小 | Smith 2018 提出。在小数据集上收敛更快、精度更高。fast.ai 推荐。 |

**几乎总是需要 Warmup（热身）**：前 N 步（N=1000 或 1 epoch）把 lr 从 0 线性升到最大值。这对 Transformer 特别重要——没有 warmup 会在训练初期直接发散（loss 跳到 inf）。原因是 LayerNorm 让梯度在初期不稳定。

### Q9：如何判断应该用「经典 ML」还是「深度学习」？一个实用的决策树。

**答**：下面是一个可以直接用的决策流程（Yann LeCun 在多次访谈中也表达过类似观点）：

`
你的数据是什么类型?
|
+-- 表格 / 结构化数据（列是特征，行是样本）?
|       |
|       +-- 样本数 < 100 万 -> **LightGBM / XGBoost / CatBoost**（默认首选）
|       |
|       +-- 样本数 > 100 万, 特征数量巨大, 或有空间结构
|           -> 先试 XGBoost baseline, 再试 TabNet / MLP / Transformer
|
+-- 图像 / 视频?
|       |
|       +-- 有预训练模型可用（几乎总是有）-> **微调 ResNet / ViT / ConvNeXt**
|       |
|       +-- 完全自定义领域 + 无预训练 -> 从零训 CNN（小数据）或 ViT（大数据）
|
+-- 文本（句子 / 段落 / 文档）?
|       |
|       +-- 英文或主流语言 -> **微调 BERT / RoBERTa / 小 LLM**
|       |
|       +-- 小语种 / 专业领域 -> 先试 BoW + LR baseline，有足够数据再上 Transformer
|
+-- 语音 / 音频?
|       -> **Whisper（有预训练）或 CNN-RNN / Conformer**
|
+-- 时间序列（股票/传感器）?
        |
        +-- 有强季节性/周期性 -> **Prophet / ARIMA / LightGBM with time features**
        |
        +-- 复杂长依赖 + 大量数据 -> 1D CNN / LSTM / Temporal Fusion Transformer
`

**核心原则**：有预训练模型用预训练模型（迁移学习几乎永远赢）。没有预训练模型时，小数据偏向简单模型（LR/RF/SVM），大数据偏向深度学习。

## 本章小结

1. **完整 ML 流程**：EDA 理解数据 -> 数据切分 -> 预处理 -> 多模型 baseline -> 超参调优 -> 评估指标 -> 误差分析 -> 模型集成 -> 最终测试评估
2. **先跑 baseline**：永远先用简单模型（LR/RF/LightGBM）建立一个可超越的下限，再上深度学习
3. **选择合适的指标**：Accuracy 在不平衡数据上会骗人，用 Precision/Recall/F1/AUC
4. **精度上不去时的排查顺序**：查数据质量 -> 查分布 -> 判断欠/过拟合 -> 调超参 -> 换模型 -> 加数据
5. **XGBoost / LightGBM 是表格数据王者**，CNN/Transformer 是非结构化数据王者
6. **训练深度学习的关键技巧**：AdamW、Warmup + Cosine Annealing、Weight Decay、Gradient Clipping、Early Stopping
7. **Dropout / BN / Weight Decay**是三种正则化手段，常常配合使用
8. **最重要的一句话**：Garbage in, garbage out —— 数据质量和特征工程，比模型架构更决定最终结果
