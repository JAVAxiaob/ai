# 第8章：图像压缩

> **面向零基础读者**：一张 1920×1080 的彩色照片需要约 6MB（1920×1080×3）存储空间，但 JPEG 格式只需 300KB——压缩率 20:1！人眼却几乎看不出区别。图像压缩的核心思想：**利用图像中的冗余（空间/统计/视觉），去掉人眼不敏感的信息**。

---

## 一、冗余的类型

### 1.1 空间冗余（Spatial Redundancy）

**问题**：相邻像素高度相关——知道左边像素是 (120, 130, 125)，右边像素很大概率也是接近的值。

**量化**：
```
相邻像素差的直方图（对自然图像）：
差值分布:
  -5: ███
  -2: ████████
   0: ████████████  ← 最常见！大量相邻像素相等或接近
  +2: ████████
  +5: ███
```

**利用方法**：预测编码（DPCM）、变换编码（DCT/DWT）。

---

### 1.2 统计冗余（Statistical Redundancy）

**问题**：不是所有灰度值出现的概率相等——可以用更少的比特编码高频值。

**例**：如果一张图像有：
- 80% 的像素是 127（背景灰色）
- 10% 的像素是 255（白色物体）
- 10% 的像素是 0（黑色边缘）

| 符号 | 概率 | 固定长编码(2bit) | ✅ Huffman 编码 |
|------|------|-----------------|----------------|
| 127  | 0.8  | 00              | 0              |
| 255  | 0.1  | 01              | 10             |
| 0    | 0.1  | 10              | 11             |
| -    | -    | -               | -              |
| 平均 | -    | 2 bit/像素     | 0.8×1+0.1×2+0.1×2 = 1.2 bit/像素 |

**熵（Entropy，信息论下限）**：
```
H = - Σ p_i · log₂(p_i)
  = - (0.8·log₂0.8 + 0.1·log₂0.1 + 0.1·log₂0.1)
  = - (0.8·(-0.32) + 0.1·(-3.32) + 0.1·(-3.32))
  = 0.256 + 0.332 + 0.332
  = 0.92 bit/像素

理论极限：任何无损编码不能优于此值。
Huffman ≈ 1.2 bit/像素 → 接近理论最优（但Huffman要求整数字节，有小 overhead）
```

**利用方法**：Huffman 编码、算术编码、LZW（Lempel-Ziv-Welch）。

---

### 1.3 视觉冗余（Psychovisual Redundancy）

**核心洞察**：人眼对不同信息的敏感度不同——可以丢掉人眼"看不到"的信息！

| 信息 | 敏感度 | 策略 |
|------|--------|------|
| 亮度(Y) | ✅ 高（人眼对亮度细节敏感） | 保留更多比特 |
| 颜色(Cb/Cr) | ❌ 低（对颜色细节不敏感） | 降采样 4:2:0 |
| 低频信息 | ✅ 高（整体结构） | 保留 |
| 高频信息 | ❌ 低（精细纹理/噪声） | 量化得更粗 |
| 平滑区域 | ✅ 高（容易察觉变化） | 精确编码 |
| 复杂纹理区域 | ❌ 低（掩盖效应） | 粗编码 |

**利用方法**：JPEG 的量化表（对高频系数量化步长更大）、MP3 的心理声学模型。

---

## 二、压缩分类

| 类型 | 定义 | 典型方法 | 压缩率 | 质量 |
|------|------|---------|--------|------|
| **无损（Lossless）** | 可精确重建原图 | Huffman, LZW, PNG, Run-length | 2:1 ~ 5:1 | 完美 |
| **有损（Lossy）** | 允许信息损失，追求高压缩率 | JPEG, JPEG2000, WebP | 10:1 ~ 100:1 | 可调（视觉无损 ~ 明显伪影） |
| **近无损（Near-lossless）** | 每个像素误差 ≤ T | 预测 + 受限量化 | 5:1 ~ 10:1 | 可证明误差范围内 |

## 三、Huffman 编码：最优前缀码

**算法**：
```
1. 统计每个符号的频率 → 叶节点
2. while 节点数 > 1:
   a. 取两个最小频率的节点
   b. 创建新节点，频率 = 两者之和
   c. 新节点的左子 = 较小节点（标记为 0），右子 = 较大节点（标记为 1）
3. 从根到叶的路径 = 该符号的编码

例：A(0.5), B(0.25), C(0.15), D(0.10)

     ● (1.0)
    / \
   0/   \1
  ●(0.5) ●(0.5) ← A 和 new
         / \
        0/   \1
       ●(0.25) ●(0.25) ← B 和 new2
              / \
             0/   \1
           ●(0.15)●(0.10) ← C, D

编码: A=0, B=10, C=110, D=111
平均 = 0.5×1 + 0.25×2 + 0.15×3 + 0.10×3 = 1.7 bit/symbol
熵 H ≈ 1.74 bit/symbol → Huffman 非常接近理论最优！
```

**前缀码性质**：任何编码不是其他编码的前缀 → 解码时无需分隔符，从左到右唯一解析。

## 四、JPEG（最常见有损压缩）

### 4.1 JPEG 流程（12步）

```
输入: RGB 彩色图像

1. RGB → YCbCr 颜色空间转换
2. Cb/Cr 4:2:0 降采样（2×2块共享一个Cb/Cr）
3. 每个通道分 8×8 块
4. 对每个块做 2D DCT:
       F(u,v) = (1/4) · C(u) · C(v) · Σ Σ f(x,y) · cos(...) · cos(...)
       C(0) = 1/√2, C(k>0) = 1
5. 系数量化（核心"有损"步骤！）:
       F_q(u,v) = round(F(u,v) / Q(u,v))
       其中 Q 是 8×8 量化表，对低频(Q小)保留精度，对高频(Q大)粗略量化
6. Zig-zag 扫描（将8×8重排为1×64，按频率从低到高）
       ▷ 1  2  6  7 ...
       ▷ 3  5  8 ...
       ▷ 4  9  ...
       好处：0系数集中在尾部 → 游程编码高效
7. DC系数差分编码：当前块DC - 上一块DC（相邻块DC高度相关→差值小）
8. 对DC差值做 Huffman 编码
9. 对AC系数做 Run-Length + Huffman:
       格式: (run, size, value) 例如 (3, 2, 5) = 三个零后是2比特的5
10. 霍夫曼编码所有符号
11. 加入文件头（量化表、Huffman表、图像信息）
12. 输出 .jpg 文件

解码: 反向执行上述步骤（去霍夫曼 → 反游程 → 反量化 → IDCT → 拼块 → YCbCr→RGB）
```

### 4.2 JPEG 量化表（Q表）

**典型 Q50 表（中等质量）**：
```
[16  11  10  16  24  40  51  61]   ← 左上=DC/最低频 → Q小=保留精度
[12  12  14  19  26  58  60  55]
[14  13  16  24  40  57  69  56]
[14  17  22  29  51  87  80  62]
[18  22  37  56  68 109 103  77]
[24  35  55  64  81 104 113  92]
[49  64  78  87 103 121 120 101]
[72  92  95  98 112 100 103  99]   ← 右下=最高频 → Q大=粗略量化
```

**直觉**：
- Q小 → 量化后值 ≈ 原值 → 精确但比特多
- Q大 → 量化后很多 0 → 压缩率高但信息损失
- 调整 JPEG 的"质量参数" = 整体缩放 Q 表

**典型质量 vs 压缩率 vs 文件大小（1920×1080）**：

| 质量 | 典型文件大小 | 压缩率 | 视觉效果 |
|------|------------|--------|---------|
| 100 | 2-3 MB | 2:1 | 几乎无损 |
| 95 | 800 KB | 7:1 | 视觉无损 |
| 85 | 400 KB | 15:1 | 高质量（手机/网络默认） |
| 75 | 250 KB | 24:1 | 较好，仔细看有模糊 |
| 50 | 150 KB | 40:1 | 可见方块效应 |
| 25 | 80 KB | 75:1 | 严重伪影，边缘模糊 |
| 10 | 40 KB | 150:1 | 不可用 |

## 五、DCT 变换：为什么是 8×8？

**DCT（离散余弦变换）** = 傅里叶变换的"实数版"，只使用余弦函数。

**DCT vs FFT**：
- DCT 输出实数（FFT输出复数）→ 存储减半
- DCT 有更好的能量紧凑性：自然图像的大部分能量集中在少数低频 DCT 系数
- 8×8 DCT = 对每个 8×8 块独立变换（块大小的权衡：大=更好压缩但计算量大+块边界伪影）

**为什么不是 4×4 或 16×16？**
- 4×4：太小 → 压缩率不足（相邻块相关性仍高）
- 8×8：历史最优（1980年代计算机能力 + 压缩率/质量平衡），现在仍是事实标准
- 16×16：更大 → 稍好压缩率，但明显可见"块边界"（块效应更严重）

## 六、游程编码（Run-Length Encoding, RLE）

**思想**：连续相同符号用（长度，值）表示。

```
输入（Zig-zag后，0很多）：
[42, 0, 0, 0, 5, 0, 0, 3, 0, 0, 0, 0, 0, 0, ..., EOB]

编码: (0,42), (3,5), (2,3), (0,EOB)
含义: 0个零后是42; 3个零后是5; 2个零后是3; 到达块结束
```

RLE + Huffman = JPEG 中 AC 系数的标准编码方式。

## 七、本章函数完整参考

### 1. `dct_2d(block)` / `idct_2d(block)`

**功能**：手动实现 2D DCT（用于教学）。

**DCT-II 公式**：
```
F(u,v) = (2/√(N·M)) · C(u) · C(v) ·
         Σ(x=0..M-1) Σ(y=0..N-1) f(x,y) ·
         cos((2x+1)uπ/(2M)) · cos((2y+1)vπ/(2N))

C(0) = 1/√2, C(k) = 1 for k>0
```

---

### 2. `jpeg_simulation(img, quality=85)`

**功能**：完整 JPEG 流程模拟（不含文件格式/Huffman优化，仅核心变换+量化）。

**参数 quality**：映射为 Q 表的整体缩放（OpenCV 实际使用公式）。

---

### 3. `huffman_encode(text)` / `huffman_decode(encoded, tree)`

**功能**：文本/符号序列的霍夫曼编码。

**输出**：(编码字典, 编码结果比特串)

---

### 4. `huffman_image(img)`

**功能**：将霍夫曼编码应用于图像像素值（仅统计冗余压缩，空间冗余未利用 → 压缩率有限）。

**注意**：实际 PNG/JPEG 都不会直接对像素值霍夫曼编码——而是先变换/预测，再对残差/系数编码。

---

### 5. `run_length_encode(img)` / `run_length_decode(encoded, shape)`

**功能**：简化版游程编码（对二值/灰度图像有效，对彩色自然图像效果有限）。

---

### 6. `compression_analysis(img, quality_values=[10, 30, 50, 70, 90])`

**功能**：不同 JPEG 质量下的文件大小、PSNR、可视化对比。

**PSNR（峰值信噪比）**：
```
MSE = (1/MN) Σ Σ (I_original - I_compressed)²
PSNR = 10 · log₁₀(255² / MSE)  (dB)

PSNR > 40 dB: 视觉无损
PSNR 30-40 dB: 高质量
PSNR 20-30 dB: 可接受
PSNR < 20 dB: 严重质量损失
```

---

### 7. `block_dct_idct_visualize(img, block_size=8)`

**功能**：可视化 JPEG 的块效应——在极低质量下，8×8 块边界明显可见。

## 八、JPEG2000 vs JPEG：小波 vs DCT

| 方面 | JPEG | JPEG2000 |
|------|------|---------|
| 变换 | 8×8 DCT（块变换） | DWT（全局/大tile变换） |
| 块效应 | ✅ 有（低质量时明显） | ❌ 无（或极轻微） |
| 压缩率 | 好 | 更好（同等质量少20-30%） |
| 渐进传输 | 有限（渐进式JPEG支持但不常用） | ✅ 原生支持（分辨率+质量可扩展） |
| 感兴趣区域 | 不支持 | ✅ 支持（某区域可设为更高质量） |
| 复杂度 | 低 | 较高（小波 + 算术编码 + EBCOT） |
| 生态/支持 | 无处不在 | 有限（浏览器支持不佳） |
| 专利 | 已过期 | 部分专利（已宽松授权） |

## 九、初学者常见问题解答

### Q1: JPEG 的"质量 85"到底是什么意思？为什么不直接说比特率？

**答**："质量" = JPEG 最直观的用户接口（你在 Photoshop/画图/手机中看到的都是它），但不同实现中"质量→Q表"的映射不完全相同。

**典型映射（IJG/libjpeg 标准）**：
```
if quality <= 0:    scale = 500 / quality  (理论上)
if quality < 50:    scale = 5000 / quality
if quality >= 50:   scale = 200 - 2*quality

Q_scaled(u,v) = floor( (Q_base(u,v) * scale + 50) / 100 )
                （限制在1-255之间）

效果: quality=50 → scale=100 → Q=Q_base（上方标准表）
      quality=75 → scale=50  → Q约为标准表一半（更精细→质量更高）
      quality=25 → scale=150 → Q约为标准表1.5倍（更粗糙→压缩率更高）
```

"比特率"（bits/pixel）是输出结果（质量→压缩→实际比特数），不是输入参数——所以不同内容图片在相同"质量"下文件大小可能相差很大（如蓝天 vs 高楼照片）。

### Q2: 为什么压缩后文件更小了？信息去哪了？

**答**：以 JPEG 为例，分两类：

**无损部分（信息保留，只是更紧凑表示）**：
1. Huffman 编码：高频符号用短编码（"127"用1位不是8位）
2. 游程编码：连续0用（次数,值）表示

**有损部分（信息永久丢失，人眼不敏感）**：
1. Cb/Cr 降采样：颜色分辨率减半（4:2:0）
2. 量化：高频 DCT 系数被"四舍五入"到粗粒度（很多变为0）

**可视化类比**：把一张精细的画复制一遍，但：
- 只用更少的颜色（丢掉精细阴影 → 降采样+量化）
- 给每个区域涂上大块平涂色（丢掉纹理 → 量化）
- 用更简洁的描述方式说"左上是一大块蓝色"而不是"像素(1,1)=蓝, (1,2)=蓝, ..."（Huffman+RLE）

### Q3: 为什么重复保存 JPEG 会越来越糊？

**答**：每次 JPEG 压缩 = 又做一次量化 → 更多信息丢失。

```
原图 → JPEG85保存 → 信息损失1%
     → JPEG85再保存 → 又损失1%（累积）
     → ...
     → 10次后 → 明显劣化（但不是线性，因为后续压缩的"空间"变小）
```

**好的工作流程**：永远保留原始/无损主文件（RAW/PNG/TIFF），JPEG 只用于最终发布。多次编辑用 PNG 或无损格式。

## 十、章节总结

```
本章知识结构
├── 冗余类型
│   ├── 空间冗余：相邻像素高度相关 → DCT/DWT/预测编码
│   ├── 统计冗余：某些值出现更频繁 → Huffman/算术/LZW
│   └── 视觉冗余：人眼对亮度>颜色，低频>高频 → 降采样+非均匀量化
├── 信息论基础
│   ├── 熵 H = -Σp·log₂p（无损压缩的理论下界 bit/像素）
│   └── 编码效率 = H / 实际平均码长
├── 无损压缩核心方法
│   ├── Huffman：最优前缀码，每次合并最小概率节点
│   ├── 算术编码：分数位表示，可达到熵（但有专利历史包袱）
│   ├── LZW：字典式，GIF/早期PDF用（专利也是问题）
│   └── 游程编码(RLE)：对0多的数据特别有效
├── JPEG 有损压缩
│   ├── 流程: RGB→YCbCr → 4:2:0降采样 → 8×8分块
│   │      → 2D DCT → 量化Q表（核心"有损"） → Zig-zag扫描
│   │      → DC差分 → AC游程+霍夫曼 → 文件
│   ├── DCT: F(u,v) = (1/4)C(u)C(v)ΣΣf·cos·cos
│   ├── 量化: F_q = round(F/Q)（关键：Q低频小、高频大）
│   ├── 质量: scale = 200-2·quality  (quality≥50)
│   └── PSNR = 10·log₁₀(255²/MSE)（dB，>40=视觉无损）
├── 常见格式对比
│   ├── PNG: 无损+透明（基于DEFLATE=LZ77+Huffman）
│   ├── JPEG: 有损照片最优（DCT+Huffman）
│   ├── WebP: Google出品（VP8帧内预测 + 变换），比JPEG小25-35%
│   ├── JPEG2000: DWT+EBCOT，质量更好但生态差
│   └── AVIF/HEIC: 基于视频编码帧内压缩，现代最佳
└── 实践原则
    ├── 主文件：PNG/RAW（无损）
    ├── 发布文件：JPEG quality=80-90（Web图像）
    ├── 避免反复JPEG保存（累积损失）
    └── 新内容优先：WebP（广泛浏览器支持）或AVIF
```
