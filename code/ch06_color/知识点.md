# 第6章：彩色图像处理

> **面向零基础读者**：人类视觉系统能分辨数百万种颜色——但计算机是如何"看到"颜色的？RGB、HSV、CMYK这些缩写背后有什么物理/心理依据？为什么做图像增强时通常在Lab空间而非RGB空间？本章给你完整解答。

## 一、颜色的本质：从物理到感知

### 1.1 三色假说（Trichromatic Theory）

**关键发现**（Young-Helmholtz，1802-1860）：人眼视网膜有三类锥体细胞（S/M/L锥），分别对短（蓝）、中（绿）、长（红）波长的光最敏感。

```
波长（nm）：380  450  500  550  600  650  700
              蓝    绿         黄    红
S锥响应：   ▇▆▅▃▁▁▁▁▁▁▁▁▁▁▁▁▁
M锥响应：   ▁▁▃▅▆▇▆▅▃▂▁▁▁▁▁▁
L锥响应：   ▁▁▁▂▃▅▆▇▇▆▅▃▂▁▁
              ↑感知颜色由三者的相对强度决定

红色（700nm）照射 → L锥强响应，M/S弱 → 感知为红色
绿色（550nm）照射 → M锥强响应，L中等，S弱 → 感知为绿色
白光 → S=M=L（均衡）→ 感知为白色/灰色
```

**结论**：任何颜色感知 = (L, M, S) 三维向量。这就是所有颜色模型的物理基础！

---

### 1.2 颜色模型总览

| 颜色模型 | 坐标含义 | 典型应用 | 是否感知均匀 |
|---------|---------|---------|------------|
| **RGB** | Red, Green, Blue（加色法） | 显示器、相机 | ❌ 不均匀 |
| **CMY(K)** | Cyan, Magenta, Yellow (Black)（减色法） | 印刷 | ❌ 不均匀 |
| **HSV** | Hue（色相）, Saturation（饱和度）, Value（明度） | 图形设计、调色 | ⚠️ 部分均匀 |
| **HSI** | Hue, Saturation, Intensity | 图像处理 | ⚠️ 类似HSV |
| **Lab / Luv** | L（亮度）, a（红-绿）, b（黄-蓝） | 颜色科学、工业 | ✅ **感知均匀** |
| **YCbCr** | Y（亮度）, Cb（蓝差）, Cr（红差） | JPEG, 视频 | ⚠️ 接近均匀 |

## 二、RGB vs CMY：加色 vs 减色

### 2.1 RGB（加色法——显示器）

```
黑色（不发光） → 叠加红光 → 红
                → 叠加绿光 → 绿
                → 叠加蓝光 → 蓝
红+绿 = 黄
红+蓝 = 品红（Magenta）
绿+蓝 = 青（Cyan）
红+绿+蓝 = 白

R=255
|   G=255  白■
|     /
|   /
| /
● 黑(0,0,0)  B=255
```

### 2.2 CMY（减色法——印刷）

```
白纸（反射全光） → 涂Cyan墨 → 吸收红光 → 剩蓝绿 = 青色
                → 涂Magenta → 吸收绿光 → 剩红蓝 = 品红
                → 涂Yellow → 吸收蓝光 → 剩红绿 = 黄色
C+M = 蓝（吸收红+绿）
C+Y = 绿（吸收红+蓝）
M+Y = 红（吸收绿+蓝）
C+M+Y = 黑（理论上，但实际油墨不纯 → 加K=Black）
```

**转换公式**：
```
CMY = (1, 1, 1) - RGB   （归一化到0-1）

CMYK：
K = min(C, M, Y)
C' = (C-K)/(1-K), M' = (M-K)/(1-K), Y' = (Y-K)/(1-K)
```

## 三、HSV/HSI：将颜色从亮度中分离

### 3.1 为什么需要 HSV？

**RGB 的问题**：改变图像亮度需要同时修改 R、G、B 三个通道，无法独立控制"颜色"和"亮度"。

**HSV 的优势**：
- H（Hue，色相） = 0~360° 的色环，纯颜色信息（红、黄、绿、蓝...）
- S（Saturation，饱和度） = 0~1，颜色的"纯度"，0=灰色，1=纯色
- V（Value，明度） = 0~1，亮度，0=黑，1=最亮

**直觉**：H = "什么颜色"？S = "颜色鲜艳吗"？V = "亮不亮"？三者完全独立！

### 3.2 RGB → HSI 转换

```
设 R, G, B ∈ [0, 1]

I = (R + G + B) / 3   （Intensity = 平均亮度）

S = 1 - (3/(R+G+B)) · min(R, G, B)  （Saturation）

H = θ       if B ≤ G
  = 360-θ   if B > G
其中 θ = arccos( (2R-G-B) / (2·√((R-G)²+(R-B)(G-B))) )

特殊情况：
- S = 0 → H = 0（灰色，无颜色）
- R=G=B → 灰色
```

### 3.3 颜色增强的最佳实践

✅ **在 HSV/HSI 空间只增强 V 通道**（而不是分别增强R/G/B）

理由：
- 避免三个通道独立增强导致的色偏
- 保持颜色（H和S）不变，只改变亮度
- 视觉自然，无假色

❌ 错误做法：分别对 R/G/B 做直方图均衡化 → 颜色比例被破坏 → 色偏严重

## 四、Lab 颜色空间：感知均匀的"黄金标准"

### 4.1 什么是"感知均匀"？

**问题**：在 RGB 中，两个颜色的欧氏距离不对应人类感知的差异。

```
RGB(100,100,100) 和 RGB(110,100,100) 的差异 = 10 → 人眼几乎看不出
RGB(200,200,200) 和 RGB(210,200,200) 的差异 = 10 → 人眼同样几乎看不出
但...
在暗区域，10 的差异可能很明显；在亮区域，可能完全不可见
```

**CIE Lab（1976）**：专门设计使空间中两点的欧氏距离**正比于人类感知的颜色差异**。

```
L = 0~100 （亮度，0=黑，100=白）
a = -128~127 （绿←→红，负=绿，正=红）
b = -128~127 （蓝←→黄，负=蓝，正=黄）
```

**ΔE（Delta E） = √(ΔL² + Δa² + Δb²)**
- ΔE < 1：不可感知
- ΔE = 1~3：可感知但可接受
- ΔE > 6：明显色差

### 4.2 RGB → Lab 转换（两步法）

```
Step 1: RGB → XYZ（CIE 1931 标准观察者三刺激值）
[X]   [0.4125 0.3576 0.1805] [R]
[Y] = [0.2126 0.7152 0.0722]·[G]  ← Y = 亮度通道（权重来自人眼对绿最敏感）
[Z]   [0.0193 0.1192 0.9505] [B]

Step 2: XYZ → Lab（非线性压缩，模拟人眼对数响应）
f(t) = t^(1/3)                  if t > δ
      = 7.787·t + 16/116        otherwise
（δ = (6/29)³ ≈ 0.008856，一小段线性修正避免t=0处奇异）

L = 116 · f(Y/Yn) - 16
a = 500 · (f(X/Xn) - f(Y/Yn))
b = 200 · (f(Y/Yn) - f(Z/Zn))

其中 Xn, Yn, Zn = D65标准白光的三刺激值（参考白点）
```

## 五、YCbCr：视频压缩的事实标准

**核心思想**：人眼对亮度细节比对颜色细节敏感得多 → 可以对颜色通道降采样而不明显影响质量。

```
Y  =  0.299·R + 0.587·G + 0.114·B    （亮度 = 加权平均，绿权重最大因为人眼对绿最敏感）
Cb = -0.169·R - 0.331·G + 0.500·B + 128  （B - Y 的"色差"）
Cr =  0.500·R - 0.419·G - 0.081·B + 128  （R - Y 的"色差"）

恢复:
R = Y + 1.402·(Cr-128)
G = Y - 0.344·(Cb-128) - 0.714·(Cr-128)
B = Y + 1.772·(Cb-128)
```

**降采样格式**（JPEG/H.264 中常用）：
- YCbCr 4:4:4 = 每个像素完整Y、Cb、Cr（无损颜色，3字节/像素）
- YCbCr 4:2:2 = 水平方向每2个像素共享一个Cb/Cr（2字节/像素，人眼几乎不可察觉）
- YCbCr 4:2:0 = 2×2块共享一个Cb/Cr（1.5字节/像素，JPEG默认）

## 六、伪彩色（Pseudocolor）：把灰度映射为颜色

**目的**：增强人眼对灰度微小差异的分辨力（人眼对颜色变化比灰度变化敏感约10倍！）。

**方法**：将 0-255 的灰度值通过查找表（LUT）映射为 (R,G,B)。

**常见 colormap**：

| 名称 | 映射逻辑 | 典型应用 |
|------|---------|---------|
| Jet | 蓝→青→绿→黄→红 | 传统热力图（注意：人眼对黄感知最亮但jet在此处不是最大，会误导） |
| Viridis | 感知均匀，绿→黄 | 现代科学可视化（推荐替代jet） |
| Hot | 黑→红→黄→白 | 温度显示 |
| Cool | 青→品红渐变 | 美学用途 |
| Gray | 等比例 → 无颜色 | 普通显示 |

## 七、彩色图像增强：正确做法 vs 错误做法

| 目标 | 错误做法 | ✅ 正确做法 | 理由 |
|------|---------|----------|------|
| 提高亮度 | 对 R/G/B 各+30 | 在 HSV 中提高 V，或在 Lab 中提高 L | R/G/B 独立调整可能破坏颜色比例 |
| 增强对比度 | 对 R/G/B 各做 hist EQ | 在 HSV 中对 V 做 CLAHE，或在 Lab 对 L 做增强 | 对三通道独立均衡化会产生严重色偏 |
| 去噪 | 对 R/G/B 各做高斯模糊 | 在 Lab 对 L 做边缘保持平滑（如双边滤波） | 噪声主要在亮度通道，Cb/Cr噪声小且人眼不敏感 |
| 锐化 | 对 R/G/B 各做 USM | 对 Lab 的 L 通道做 USM | 锐化颜色通道会引入彩色边缘伪影 |

## 八、基于颜色的分割

### 8.1 HSV 阈值分割

**思路**：如果想分割"红色物体"，只需在 HSV 空间中找 H 在红色范围（~0° 和 ~360°，因为红色在色环两端）且 S 较大的像素。

```
例：分割红色物体

在 HSV（H∈[0,180]，S,V∈[0,255]）：
lower1 = (0,   100, 100)    ← 红色范围起点
upper1 = (10,  255, 255)    ← 红色范围终点1
lower2 = (170, 100, 100)    ← 红色在色环另一端
upper2 = (180, 255, 255)

mask = inRange(hsv, lower1, upper1) | inRange(hsv, lower2, upper2)
result = bitwise_and(img, img, mask=mask)  ← 只保留红色物体
```

**优势**：
- 对光照变化鲁棒（V通道变化不影响H和S）
- 直观，可手动调参

**局限**：
- 需要目标颜色与背景有显著差异
- 颜色相近时会误分割

---

### 8.2 区域生长（彩色版）

```
输入: 种子点 (sr, sc) 和 阈值 T
1. 种子颜色 = img[sr, sc] = (R0, G0, B0)
2. 对每个邻居像素 (x, y):
   diff = ||img[x,y] - 种子颜色||₂  (欧氏距离)
   if diff < T: 标记为目标区域
3. 用新加入的像素作为新种子继续扩展
4. 直到无新像素加入
```

### 3. `rgb_to_cmy(img)`：RGB→CMY 转换

```
C = 255 - R, M = 255 - G, Y = 255 - B
```

```
K = 1 - max(R, G, B)

```

| weighted | 0.299·R + 0.587·G + 0.114·B | ✅ 标准，人眼对绿最敏感 |
| average | (R+G+B)/3 | ❌ 不自然（绿色会显得太暗） |
| max | max(R,G,B) | 会产生奇怪结果 |

### 8. `pseudocolor(img, colormap='jet')`：伪彩色映射

## 十、初学者常见问题解答

### Q1: 为什么OpenCV的HSV中H是0-179而不是0-359？

**答**：OpenCV 用 uint8 存储，最大值255。为了将 0-360° 映射到 0-255 且保留精度，他们选择除以2（不是最合理的设计，但已成事实标准）。所以：

- OpenCV HSV: H ∈ [0, 179], S,V ∈ [0, 255]
- 标准 HSV: H ∈ [0, 360°), S,V ∈ [0, 1] 或 [0, 255]

**转换**：OpenCV_H = round(Standard_H / 2)

### Q2: 为什么灰度转换公式有这么多"奇怪"的系数（0.299, 0.587, 0.114）？

**答**：来自人眼的光谱响应。人眼对绿光最敏感（555nm 峰值），对红光中等，对蓝光最不敏感。所以一个像素的"心理亮度"应该是加权的——绿色给最大权重。

```
ITU-R BT.601（SDTV）系数：0.299·R + 0.587·G + 0.114·B
ITU-R BT.709（HDTV）系数：0.2126·R + 0.7152·G + 0.0722·B （更精确）

直觉验证：
亮绿色 RGB=(0,255,0) → 灰度 = 0.299×0 + 0.587×255 + 0.114×0 ≈ 150
亮蓝色 RGB=(0,0,255) → 灰度 = 0.299×0 + 0.587×0 + 0.114×255 ≈ 29

亮绿色在人眼中看起来确实比亮蓝色亮得多！
```

### Q3: 做图像识别/深度学习时，我应该用什么颜色空间？

**答**：几乎总是 **直接用 RGB**（或BGR，OpenCV默认）。

原因：
1. 现代深度学习模型（CNN）会自动学习合适的颜色特征表示——不需要你手动设计颜色空间
2. 从RGB转换到其他空间是线性/非线性变换，CNN可以学习到等价或更好的变换
3. 大多数预训练模型（ImageNet训练的ResNet等）使用RGB输入
4. 存储和读取简单：JPEG/PNG本身就是RGB/BGR

**例外**：光照变化大的任务 → 有时对亮度归一化后再送网络会有小幅提升。

```
本章知识结构
├── 颜色感知基础
│   ├── 三色假说（Young-Helmholtz）：S/M/L 锥体细胞
│   ├── 颜色是三维感知：任一颜色 = (L, M, S) 响应向量
│   └── 人眼对亮度比对颜色更敏感（视觉系统的带宽分配）

│   ├── CMY(K)：减色法，印刷

│   ├── Lab/Luv：感知均匀（ΔE 正比于人眼感知）→ 颜色科学标准
│   └── YCbCr：Y亮度 + Cb/Cr色差 → JPEG/视频压缩标准（4:2:0降采样）
├── 彩色图像处理最佳实践
│   ├── ✅ 在 Lab/HSV 增强 L/V 而非 R/G/B 独立增强
│   ├── ✅ 对 L 通道做去噪/锐化，Cb/Cr 可不处理或弱处理
│   ├── ❌ 禁止对三通道独立均衡化（严重色偏）
│   └── 伪彩色：Jet→Viridis（注意Jet的感知非均匀性）
├── 基于颜色的分割

│   └── 区域生长：颜色欧氏距离 < T 则合并
└── 工程实践
    ├── OpenCV默认是BGR（不是RGB！注意交换通道）
    ├── OpenCV HSV: H∈[0,179], S/V∈[0,255]
    ├── 深度学习：通常直接用RGB输入，无需转换
    └── 灰度化标准公式：Gray = 0.299·R + 0.587·G + 0.114·B
```
